# The `Depends` field of the pinned Odoo nightly `.deb`, normalized.
#
# Layer (a) of the Dockerfile installs these packages *before* the `.deb`
# itself is installed in layer (b), so that an Odoo bump re-sends only the
# package and not the ~480 MiB of dependencies underneath it (issue #153,
# ADR 0013). The guard test `tests/test_dockerfile_layers.py` fails when
# this file and layer (a)'s package list stop agreeing.
#
# Format -- this is a contract with the odoo-bump workflow, which merges the
# new `.deb`'s `Depends` into this file when it pins one (issue #156, script
# `.github/scripts/odoo_deb_depends.py`). Read it as:
#
#   * One `Depends` entry per line, one package name per line, sorted with
#     `LC_ALL=C`.
#   * A line whose first non-blank character is `#` is a comment, and a
#     blank line is ignored.
#   * Everything after `  # ` on a package line is notes, separated by
#     `; `. A note is `<kind>: <value>`. A value is prose and may contain a
#     semicolon, as long as what follows the semicolon does not itself
#     start with `word:` -- that opens a new note, so that a misspelled
#     kind is reported rather than swallowed as prose. A note is one of:
#       - `alternatives: a | b | c` -- the entry was an alternatives group,
#         written here exactly as the `.deb` wrote it. The name on the left
#         is the alternative apt resolves on the pinned base image, which is
#         not always the first one: bookworm has no `python3-lxml-html-clean`.
#       - `version: (>= 1.2)` -- a version constraint the name dropped. It is
#         recorded, not enforced: the base image's Debian release decides the
#         version, and a constraint it cannot satisfy fails the build in (b).
#       - `qualifier: :any` -- an architecture qualifier the name dropped.
#         The image is single-arch per build, so the plain name installs.
#       - `deferred: <why, and until when>` -- layer (a) does not install
#         this name at all. A nightly that gains a dependency would
#         otherwise rebuild the ~480 MiB layer (a) on a routine bump; the
#         entry is recorded here, apt installs it into (b), and it is folded
#         into (a) at the next event that rebuilds (a) anyway (ADR 0013).
#       - `dropped: <why, and until when>` -- the mirror of `deferred`: the
#         `.deb` no longer depends on this name, and layer (a) still
#         installs it. Removing it would rebuild (a) on a routine bump, so
#         the line stays until the next event that rebuilds (a) anyway.
#       - `satisfied-by: <package>` -- layer (a) installs `<package>` instead
#         of this name, because `<package>` provides it. Used for
#         `postgresql-client`, which is a real metapackage tracking the
#         newest PostgreSQL in the pgdg repository: installing it by name
#         would add a second client beside the pinned `postgresql-client-16`.
#
#   * The `# source:` line below names the `.deb` this file was generated
#     from. It is provenance, not a pin, and the static tier does not fail
#     when it falls behind `ARG ODOO_DEB_VERSION`: the build jobs need the
#     static tier, so a red one would cost the weekly bump the image build
#     that proves the new package. A list behind the pin costs layer (b)
#     size and nothing else. The bump workflow rewrites the line itself, but
#     only on a bump that moved a dependency: one whose `Depends` normalizes
#     to this same list leaves the file, and its pull request's diff, alone.
#
#   * The merge is `.github/scripts/odoo_deb_depends.py`, run by the weekly
#     odoo-bump on the same package it hashes. To do it by hand, read the
#     new package's field and hand it to the script:
#
#         curl -fsSL "https://nightly.odoo.com/18.0/nightly/deb/\
#         odoo_${ODOO_DEB_VERSION}_all.deb" -o /tmp/odoo.deb
#         dpkg-deb -f /tmp/odoo.deb Depends \
#           | python3 .github/scripts/odoo_deb_depends.py \
#               --list odoo18ce/odoo-deb-depends.txt \
#               --dockerfile odoo18ce/Dockerfile --depends-field - \
#               --deb-version "${ODOO_DEB_VERSION}"
#
#     A package the new `.deb` adds gets a `deferred` note rather than a
#     place in layer (a), and one it no longer names gets a `dropped` note
#     rather than leaving (a): a weekly bump must not rebuild the big layer.
#
#     One rule needs a decision rather than a rewrite, so the script makes
#     none and says so in the pull request body instead: which alternative
#     of a group the base image's apt actually resolves (`apt-cache policy
#     <name>` inside the base image answers it). Folding a `deferred` entry
#     into layer (a) is the other -- that one updates layer (a)'s list in
#     the Dockerfile and EXPECTED_SEQUENCE in the guard test to match.
#
#   * A dependency this file misses is not a broken build. Layer (b)
#     installs the `.deb` with apt, which pulls whatever is still absent --
#     into (b), where it makes the Odoo layer bigger and nothing else.
#
# source: odoo_18.0.20260930_all.deb
